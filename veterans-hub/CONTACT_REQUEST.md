## לפני שמתחילים
`git pull origin ccr-d452e790-ntiise`. הרשימה נמצאת ב-`veterans-hub/research/requests/no_contact_list.json` (id, name, town, source_url, supplier). הרשומות המלאות נמצאות ב-`data/services.js`.

## סדר עדיפויות
1. **32 הרשומות שאינן ספקים (`supplier: false`):** עמותות, תוכניות ושירותים. אלה הכי חשובות.
2. **85 ספקי Shikum.Me (`supplier: true`):** מכוני כושר, סטודיו, בריכות וגלישה. לכל אחד לחפש טלפון של העסק ואתר או עמוד עסק רשמי, ולבדוק שהעסק עדיין פעיל באותו יישוב. אם מופיע ברשימה הרשמית של Shikum.Me יותר מסניף אחד, לרשום את הסניף שתואם ל-town.

## מה לרשום לכל id
קובץ: `veterans-hub/research/contact_fill.json`, אובייקט `{ "<id>": { ... } }` עם השדות:
- `phone`, `email`, `website`: **רק פרטי קשר ארגוניים או עסקיים, כפי שהם מופיעים במקור רשמי** (אתר העסק, עמוד עסק מאומת, רשימה ממשלתית). לא נייד פרטי של אדם בשמו.
- `how_to_apply`: משפט אחד קונקרטי על הצעד הראשון (למשל "מתקשרים ומבקשים לתאם אימון ניסיון", או "ממלאים טופס בעמוד התוכנית").
- `source_url`: העמוד שבו נמצאו הפרטים.
- `status`: אחד מהבאים:
  - `active`: נמצא ופעיל;
  - `closed`: נסגר או הסתיים;
  - `not_found`: אי אפשר למצוא דרך פנייה;
  - `moved`: עבר כתובת. במקרה הזה לעדכן את `town`.
- `note`: קצר, רק אם יש משהו חשוב.

**פרטיות:** בלי שמות של אנשים פרטיים, ובלי מספרים שמופיעים רק בפוסטים או בתגובות.

## איך להחזיר
דוחפים רק את `research/contact_fill.json` לאותו ענף, ולא נוגעים בשאר הקבצים.

**סיכום בסוף:**
- כמה רשומות קיבלו פרטים;
- כמה נסגרו;
- כמה לא נמצאו.

מה שיחזור כ-`closed` יוסתר. מה שיחזור כ-`not_found` יוצא מההתאמה האישית ויישאר רק בחיפוש.
