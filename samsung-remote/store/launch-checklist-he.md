# רשימת צעדים להשקה ב-Google Play — שלט לטלוויזיה

המדריך מסודר לפי סדר הביצוע. סמנו ✅ ליד כל שלב שסיימתם. כל הטקסטים המוכנים נמצאים בתיקייה `store/`:
- `listing-he.md` / `listing-en.md` — שם, תיאור קצר, תיאור מלא, "מה חדש", קטגוריה ותגיות
- `screenshots-plan.md` — אילו צילומי מסך לצלם ומה לכתוב עליהם
- `data-safety.md` — תשובות מוכנות לכל טפסי "תוכן האפליקציה"
- `pricing.md` — מחיר ה-Pro: המלצה, איך התמחור ב-Play עובד, וטבלת מחירים לפי מדינה
- `privacy-policy.html` — מדיניות הפרטיות (מפורסמת ב-https://dimslider.github.io/remote-privacy/)

> **לוח זמנים מציאותי:** פתיחת חשבון ואימות — כמה ימים. בדיקה סגורה — **לפחות 14 ימים** (חובה). בקשת גישה להפצה — עד כשבוע. בדיקת האפליקציה לפני פרסום — בדרך כלל כמה ימים, לפעמים יותר. סה"כ: לתכנן כ-3–4 שבועות.

- [ ] חשבון Google (Gmail) שישמש לחשבון המפתח. כדאי חשבון ייעודי, ולא החשבון הפרטי היומיומי.
- [ ] תעודה מזהה (ת"ז / דרכון) לאימות זהות.
- [ ] כרטיס אשראי לתשלום דמי ההרשמה.
- [ ] טלפון אנדרואיד אמיתי (נדרש לאימות החשבון דרך אפליקציית Play Console).
- [x] כתובת מייל ליצירת קשר: `remotetvforall@gmail.com` (כבר מעודכנת בכל הקבצים).
- [ ] פרטי חשבון בנק — כדי לקבל כסף ממכירות.
- [ ] רשימה ראשונית של לפחות 15 אנשים עם טלפון אנדרואיד שיסכימו לשמש בודקים (12 חובה + רזרבה).

## שלב 1 — פתיחת חשבון מפתח ב-Play Console
1. [ ] נכנסים ל-play.google.com/console ומתחברים עם חשבון Google.
2. [ ] בוחרים סוג חשבון: **אישי (Personal)** — מתאים למפתח יחיד. (חשבון **ארגוני** מחייב מספר D-U-N-S של העסק; לחשבון אישי לא צריך D-U-N-S.)
3. [ ] משלמים דמי הרשמה חד-פעמיים של **25$**.
4. [ ] ממלאים שם מפתח (השם שיוצג בחנות מתחת לשם האפליקציה), כתובת, טלפון ומייל.
5. [ ] **אימות זהות:** מעלים תעודה מזהה לפי ההנחיות. השם חייב להתאים בדיוק לשם בכרטיס האשראי/בפרופיל התשלומים.
6. [ ] מאמתים את מספר הטלפון ואת המייל.
7. [ ] מתקינים בטלפון האנדרואיד את אפליקציית **Google Play Console** ומתחברים — כך מאמתים שיש לכם גישה למכשיר אנדרואיד אמיתי.
8. [ ] ממתינים לאישור האימות (בדרך כלל יום עד כמה ימים; מקבלים מייל).

> **חשוב:** חשבונות אישיים שנפתחו אחרי נובמבר 2023 חייבים להריץ **בדיקה סגורה עם לפחות 12 בודקים שהצטרפו, במשך 14 ימים רצופים**, ורק אז אפשר לבקש גישה להפצה לכולם (Production). זה מוסבר בשלבים 11–13.

## שלב 2 — פרופיל תשלומים (כדי למכור)
1. [ ] ב-Play Console: **הגדרות ← פרופיל תשלומים** (Settings → Payments profile) — יוצרים פרופיל סוחר (Merchant).
2. [ ] ממלאים פרטי בנק לקבלת תשלומים ופרטי מס לפי מה שמתבקש.
3. [ ] עמלת Google: 15% מהמכירות על המיליון דולר הראשון בשנה — **רק אחרי הרשמה למסלול 15%** ("15% service fee tier" בהגדרות החשבון/התשלומים; בלי הרשמה העמלה 30%). מע"מ בישראל ובמדינות רבות Google גובה ומעבירה בעצמה — המחיר שהמשתמש רואה כולל מע"מ.

## שלב 3 — יצירת האפליקציה

2. [ ] שם האפליקציה: אחד מהשמות ב-`listing-en.md` (אפשר לשנות אחר כך).
3. [ ] שפת ברירת מחדל: **English (United States) – en-US**. (העברית תתווסף כתרגום בשלב 7.)
4. [ ] סוג: **אפליקציה (App)**, לא משחק. מחיר: **חינם (Free)** — האפליקציה עצמה חינמית להורדה, והרכישה נעשית בתוכה. (שימו לב: אפליקציה חינמית אי אפשר להפוך אחר כך לבתשלום — וזה בדיוק מה שאנחנו רוצים.)
5. [ ] מאשרים את ההצהרות (מדיניות מפתחים, חוקי ייצוא) ← **יצירה**.

## שלב 4 — העלאת קובץ האפליקציה וחתימה
1. [ ] מורידים את הקובץ **`TV-Remote-play.aab`** מתוך ה-Artifacts של GitHub Actions (בריפו ← Actions ← ההרצה האחרונה שהצליחה ← Artifacts ← הורדה ופתיחת ה-zip).
2. [ ] **Play App Signing (חתימת אפליקציות של Play):** משאירים את ברירת המחדל — Google מנהלת את מפתח החתימה הסופי. הקובץ שאתם מעלים חתום ב-**upload key** (מפתח ההעלאה); את ההוראות לגביו תקבלו בנפרד. **לא לאבד את מפתח ההעלאה ואת הסיסמה שלו**, ולא לשלוח אותם לאף אחד.
3. [ ] את ההעלאה הראשונה עושים כבר במסלול הבדיקה הסגורה (שלב 11) — אין צורך במסלול נפרד קודם.

## שלב 5 — מוצר הרכישה החד-פעמית (Pro)
> המודל: ההורדה חינם, **השלט הבסיסי חינמי לתמיד**, ו-**Pro** הוא רכישה חד-פעמית (בלי מנוי, בלי פרסומות). 7 הימים הראשונים Pro פתוח לכולם בחינם; אחר כך, בלי רכישה, האפליקציה חוזרת לגרסה החינמית.
> אפשר ליצור מוצר רק **אחרי** שהועלה לפחות קובץ AAB אחד שכולל את ספריית החיוב של Google Play. לכן עושים את השלב הזה מיד אחרי ההעלאה הראשונה בשלב 11 (גם אם הגרסה עוד בבדיקה).

1. [ ] **מונטיזציה ← מוצרים ← מוצרים חד-פעמיים** (Monetize with Play → Products → One-time products; בממשק הישן: In-app products) ← **יצירת מוצר**.
2. [ ] מזהה מוצר (Product ID): **`full_unlock`** — בדיוק כך, באותיות קטנות. (אי אפשר לשנות מזהה אחרי יצירה!)
3. [ ] שם: **"Pro"** (גם בעברית: "Pro"). תיאור (עד 200 תווים): "One-time purchase: call auto-mute, lock-screen remote, widget, sleep timer, voice, typing, macros and multiple TVs. No subscription." (132 / 200 chars) / "רכישה חד-פעמית: השתקה בשיחות, שלט במסך הנעילה, ווידג'ט, טיימר שינה, קול, הקלדה, מאקרו וכמה טלוויזיות. בלי מנוי." (111 / 200 chars) (המוצר מסוג חד-פעמי שלא נצרך — non-consumable; נקנה פעם אחת ונשאר לתמיד.)
4. [ ] מחיר: לפי **`pricing.md`** — מחיר השקה מומלץ **2.99$** כמחיר ברירת מחדל, ובישראל **12.90 ₪** (כולל מע"מ). נותנים ל-Play להמיר לשאר המדינות, ואז מקלידים את המחירים המקומיים מהטבלה (עמודת 2.99$) כ-override למדינות שבטבלה. בהמשך — בדיקה של 3.99$. המחיר ניתן לשינוי בכל עת, ומי שכבר קנה לא מושפע.
5. [ ] **הפעלה (Activate)** — מוצר שלא הופעל לא יופיע באפליקציה.
6. [ ] **בודקי רישיון** (License testing): ברמת החשבון (לא בתוך האפליקציה) **הגדרות ← בדיקת רישיונות** (Settings → License testing) — מוסיפים את המיילים שלכם ושל הבודקים (אותו חשבון Google שמחובר ל-Play Store בטלפון שלהם), או את ה-Google Group של הבודקים, ושומרים.
   - בודק רישיון שקונה את Pro רואה בחלון הרכישה של Google את הכיתוב **"Test card, always approves"** (כרטיס בדיקה) — **לא מחויב בכסף אמיתי**. אם לא רואים את הכיתוב הזה — לא לאשר את הקנייה (סימן שהחשבון לא ברשימה או שעוד לא התעדכן; לוקח עד כמה שעות).
   - בודקים רגילים בבדיקה הסגורה שאינם ברשימת בודקי הרישיון **כן יחויבו** אם יקנו — לכן מוסיפים את כולם לרשימה.
   - כדי לבדוק "קנייה מחדש": ב-Play Console ← ניהול הזמנות (Order management) מחפשים את הזמנת הבדיקה ועושים לה החזר (Refund) עם ביטול הזכאות (Revoke) — ואז אפשר לקנות שוב.
   - כדי לבדוק את הגרסה החינמית (אחרי 7 הימים) בלי לחכות שבוע — לבקש מהמפתח דרך לקצר את הניסיון בגרסת בדיקה; לוודא שהשלט הבסיסי ממשיך לעבוד ושאפשרויות ה-Pro מסומנות ככאלה.

## שלב 6 — העלאת מדיניות הפרטיות לכתובת ציבורית

✅ **בוצע.** הכתובת: **https://dimslider.github.io/remote-privacy/** — מדביקים אותה ב-Play Console ← App content ← Privacy policy. (כשמעדכנים את המדיניות: מעלים קובץ `index.html` חדש לאותו ריפו `remote-privacy`.)
Google דורשת כתובת אינטרנט ציבורית (URL) למדיניות הפרטיות. כתובת המייל `remotetvforall@gmail.com` כבר מופיעה בקובץ `store/privacy-policy.html`.

**האפשרות הפשוטה והחינמית — GitHub Pages בריפו נפרד וציבורי:**
(אם הריפו של האפליקציה פרטי, GitHub Pages עליו דורש מנוי בתשלום — לכן עדיף ריפו קטן ונפרד רק למדיניות.)
1. [ ] נכנסים ל-github.com ← **New repository**. שם: `tvremote-privacy`. מסמנים **Public** ← Create.
2. [ ] בריפו החדש: **Add file ← Upload files** ← גוררים את `privacy-policy.html` ← **Commit changes**.
3. [ ] משנים את שם הקובץ ל-`index.html` (לוחצים על הקובץ ← עיפרון ← משנים שם ← Commit). אפשר גם להשאיר בשם המקורי.
4. [ ] **Settings ← Pages** ← תחת Source בוחרים **Deploy from a branch** ← Branch: **main**, תיקייה **/ (root)** ← **Save**.
5. [ ] מחכים 1–3 דקות ומרעננים. מופיעה כתובת בסגנון:
   `https://<שם-המשתמש>.github.io/tvremote-privacy/` (ואם השארתם את שם הקובץ: `.../tvremote-privacy/privacy-policy.html`).
6. [ ] פותחים את הכתובת בטלפון ובודקים שהדף נטען ושהמייל נכון.

**חלופות חינמיות:** Google Sites (יוצרים אתר ומדביקים את הטקסט), או Netlify Drop (app.netlify.com/drop — גוררים תיקייה עם הקובץ `index.html` ומקבלים כתובת מיידית).

7. [ ] מדביקים את הכתובת ב-Play Console: **תוכן האפליקציה ← מדיניות פרטיות** (App content → Privacy policy).

## שלב 8 — תוכן האפליקציה (App content)
**מדיניות ותוכניות ← תוכן האפליקציה.** כל התשובות כתובות ב-`data-safety.md`:
1. [ ] מדיניות פרטיות — הכתובת משלב 6.
2. [ ] **מודעות:** אין מודעות.
3. [ ] **גישה לאפליקציה:** כל הפונקציונליות זמינה בלי הרשאות מיוחדות (אין התחברות) + ההערה לבודקי Google (כולל ש-Pro פתוח בחינם 7 ימים, כך שהבודקים יכולים לנסות הכול בלי לקנות).
4. [ ] **סיווג תוכן (IARC):** ממלאים את השאלון — צפוי דירוג "לכל הגילאים / 3+".
5. [ ] **קהל יעד:** 13 ומעלה (13–15, 16–17, 18+). **לא** לבחור גילאים מתחת ל-13 — זה מכניס את האפליקציה לכללי Families המחמירים.
6. [ ] **בטיחות נתונים (Data safety):** "לא נאסף מידע" — כולל ההסבר על Billing/In-App Review וחלופה שמרנית, ב-`data-safety.md` §1.3. אין צורך בטופס הצהרת הרשאות (READ_PHONE_STATE אינה הרשאה מוגבלת), אבל **כן** צריך את הצהרת השירות בחזית (סעיף 8 כאן).
7. [ ] אפליקציית חדשות — לא. אפליקציה ממשלתית — לא. תכונות פיננסיות — אין. בריאות — אין. מזהה פרסום — לא.
8. [ ] **הרשאות שירות בחזית (Foreground service):** סוג "מכשיר מחובר" (Connected device) — מדביקים את הטקסטים ומעלים קישור לסרטון (תסריט של 30 שניות ב-`data-safety.md`; מעלים ליוטיוב כ"לא רשום" Unlisted).

## שלב 10 — הכנת קבוצת הבודקים
אפשר לנהל את הבודקים בשתי דרכים — בוחרים אחת:
- **רשימת מיילים:** ב-Play Console מוסיפים רשימה ומדביקים את כתובות ה-Gmail של הבודקים (כתובת חשבון Google שמחובר אצלם ל-Play Store בטלפון).
- **Google Group (מומלץ אם יש הרבה אנשים):** יוצרים קבוצה ב-groups.google.com (למשל `tvremote-testers@googlegroups.com`), מגדירים שכל אחד יכול להצטרף, ושולחים לבודקים את הקישור להצטרפות. ב-Play Console מוסיפים את כתובת הקבוצה בלבד.

- [ ] אוספים לפחות **12 בודקים — רצוי 15–20**, כי תמיד מישהו נושר.
- [ ] בודקים צריכים: טלפון אנדרואיד, חשבון Google, ועדיף טלוויזיה חכמה נתמכת בבית (Samsung / LG / Android TV / Google TV). גם בלי טלוויזיה הם נחשבים, אבל משוב אמיתי שווה יותר.

## שלב 12 — מה הבודקים צריכים לעשות
שלחו לבודקים הודעה בסגנון:
> "היי! אני משיק אפליקציית שלט לטלוויזיה ואשמח שתהיה/י בודק/ת. 1) (אם יש קבוצה: הצטרפו לקבוצה בקישור הזה). 2) פתחו בטלפון את הקישור הזה ולחצו 'הצטרפות לבדיקה' (Become a tester), עם אותו חשבון Google שמחובר ל-Play Store. 3) לחצו על הקישור להורדה ב-Google Play והתקינו. 4) נסו את האפליקציה מול הטלוויזיה — השלט הבסיסי חינמי, וב-7 הימים הראשונים גם כל אפשרויות ה-Pro פתוחות: השתקה בשיחות (בקשו ממישהו להתקשר אליכם, וגם שיחת וואטסאפ), שלט במסך הנעילה, טיימר שינה, קול, מאקרו. 5) אם תרצו לנסות את הקנייה: בחלון הרכישה צריך להופיע 'Test card, always approves' — זה אומר שלא תחויבו. אם הכיתוב לא מופיע, אל תאשרו ותכתבו לי. 6) **חשוב: אל תצאו מהבדיקה ואל תמחקו את האפליקציה במשך 14 יום.** תודה!"

- [ ] לוודא שכל אחד באמת **הצטרף** (Opt-in) — הספירה של Google היא לפי הצטרפות, לא לפי הזמנה.
- [ ] 14 הימים נספרים רק כשיש **לפחות 12 מצטרפים בבת אחת, ברצף**. אם מישהו פורש והמספר יורד מתחת ל-12 — הספירה עלולה להתאפס. לכן רזרבה.
- [ ] בקשו מהבודקים להשתמש באפליקציה כמה פעמים במהלך התקופה (Google שואלת על המעורבות שלהם).
- [ ] במהלך הבדיקה מעלים לפחות עדכון אחד שמתקן משהו מהמשוב — זה עוזר בבקשת הגישה להפצה.
- [ ] **בדיקת מקור זיהוי השיחה:** אחרי שיחת בדיקה (שיחה רגילה וגם שיחת וואטסאפ), בהגדרות האפליקציה לוחצים **"העתק מידע לאבחון תקלות"** ומדביקים בהודעה. ביומן מחפשים שורות `phone: call (…)` ובודקים מה כתוב בסוגריים: `phone state …` או `call broadcast …` = זוהה דרך הרשאת מצב הטלפון (READ_PHONE_STATE); `audio mode …` = זוהה דרך מצב השמע (בלי הרשאה, Android 12+). השורה `phone: watching calls (…) via …` מראה אילו מקורות האזינו. לאסוף תוצאות מכמה דגמים וגרסאות Android — כדי להחליט בהמשך אם אפשר להגביל את READ_PHONE_STATE ל-Android 11 ומטה.

**איסוף משוב:**
- [ ] טופס Google Forms קצר: איזו טלוויזיה, האם נמצאה אוטומטית, מה לא עבד, מה חסר, ציון 1–5.
- [ ] קבוצת וואטסאפ קטנה לבודקים — הכי מהיר לשאלות.
- [ ] בודקים יכולים גם לכתוב "משוב פרטי" בדף האפליקציה ב-Play Store — מופיע ב-Play Console תחת **דירוגים וביקורות ← משוב מבודקים**.
- [ ] לבדוק ב-**Android vitals** ובדוח **לפני השקה** (Pre-launch report) אם יש קריסות.

## שלב 13 — בקשת גישה להפצה (Production)
1. [ ] אחרי 14 ימים רצופים עם 12+ בודקים — בלוח הבקרה (Dashboard) מופיע **"בקשת גישה להפצה"** (Apply for production).
2. [ ] עונים על השאלות: איך גייסתם בודקים, כמה קל היה לגייס, איזה משוב קיבלתם ומה תיקנתם, למי מיועדת האפליקציה ומה הערך שלה, למה היא מוכנה להפצה. עונים בכנות ובפירוט (כמה משפטים לכל שאלה).
3. [ ] ממתינים לתשובה (בדרך כלל עד 7 ימים). אם נדחים — Google מסבירה מה לשפר; ממשיכים בבדיקה ומגישים שוב.

## שלב 14 — השקה (Production) בהדרגה
1. [ ] **הפצה ← ייצור (Production) ← יצירת גרסה חדשה** ← אפשר "לקדם" את הגרסה מהבדיקה הסגורה (Promote release) או להעלות AAB חדש.
2. [ ] מגדירים **השקה מדורגת** (Staged rollout): מתחילים ב-**20%** מהמשתמשים.
3. [ ] אחרי 2–3 ימים בלי קריסות ובלי ביקורות שליליות על באגים ← **50%**, ואחרי עוד כמה ימים ← **100%**.
4. [ ] אם מתגלה בעיה רצינית — **עוצרים את ההשקה** (Halt rollout), מתקנים ומעלים גרסה חדשה.
5. [ ] בודקים שהרכישה עובדת בגרסה החיה (עם חשבון בודק רישיון — "Test card, always approves", בלי חיוב), ושאחרי הרכישה מונה הניסיון מתחלף ב-Pro פעיל.
